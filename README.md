# Rust AutoWipe

[![ci](https://github.com/kafder100/RustWipe/actions/workflows/ci.yml/badge.svg)](https://github.com/kafder100/RustWipe/actions/workflows/ci.yml)
[![release](https://img.shields.io/github/v/release/kafder100/RustWipe?display_name=tag)](https://github.com/kafder100/RustWipe/releases)

Плагин автовайпов для игры **Rust** на панели **[Catalyst](https://catalystctl.com/)** (catalystctl):
расписание вайпов, выбор каталогов и файлов для удаления, остановка/запуск сервера,
история прогонов.

Плагин **привязан к серверу**, а не к панели: это вкладка внутри карточки сервера,
которая появляется только у серверов с шаблоном (яйцом) Rust. Все API-роуты живут под
`/api/plugins/rust-autowipe/servers/:serverId/…` и проверяют доступ к этому серверу.

Плагин написан под [систему плагинов Catalyst](https://docs.catalystctl.com/api/plugins/):
backend — обычный ESM без зависимостей (роуты, `scheduleTask`, файловый туннель,
коллекции), frontend — самодостаточный `frontend.mjs` без импортов.

## Возможности

| Возможность | Детали |
|---|---|
| **Привязка к серверу** | вкладка `location: 'server'` + `templateFilter: { namePattern: 'rust' }` — видна только на Rust-серверах; backend тоже отказывает серверу с шаблоном не Rust; профили и история изолированы по серверу |
| **Расписание** | еженедельно · «первый/последний N-й день недели месяца» (под Force Wipe Facepunch) · день месяца · каждые N дней (от точки отсчёта). Время — в часовом поясе профиля (IANA, например `Europe/Moscow`); не выбран — в поясе панели |
| **Выбор файлов и каталогов** | файловый пикер по реальному дереву сервера, маски `*` / `?` / `**`; `[*]`, `[?]`, `[[]` — сами символы в имени (другие скобки — обычные символы); отдельный список исключений |
| **Управление списком** | перетаскивание за `⠿`, `↑` / `↓`, правка по месту (`Enter`/`Esc`), дублирование `⧉`, удаление `×` |
| **Безопасность вайпа** | предпросмотр «что будет удалено», проверка (dry-run), окно подтверждения перед вайпом; цель на весь корень сервера запрещена; поиск путей упал или упёрся в предел — не удаляется ничего; среди найденного есть похожее на ссылку (права 777) или странное имя — вайп не начинается; сервер, остановленный плагином, поднимается при любой ошибке, а после падения панели — повторами раз в минуту |
| **Rust-пресеты** | карта · карта + блюпринты · данные игроков · полный вайп (с сохранением `cfg/server.cfg`) · данные Oxide/Carbon. Вместе с сохранением мира удаляются его запасные копии, вместе с базами — файлы `-wal` и `-shm` |
| **Сид и размер карты** | `WORLD_SEED` — случайный каждый вайп / фиксированный / по списку по очереди; `WORLD_SIZE` — фиксированный или случайный из набора. Значения пишутся в переменные шаблона перед стартом; другие переменные плагин не меняет |
| **Предупреждения в чате** | `say …` за 5, 4, 3, 2 и 1 минуту до планового вайпа; текст и окно настраиваются; перед проверкой (dry-run) отсчёта нет |
| **Порядок** | остановка → поиск путей → сид и размер → удаление → запуск (через REST API панели); команды в консоль — только когда сервер в статусе `running` |
| **История** | 200 прогонов на каждый сервер; шаги раскрываются: время, длительность фазы, метрики (пути, удалено, пропущено, ошибки), списки путей. Итог проверки хранится отдельно от итога вайпа |
| **Права** | админ панели и владелец сервера — всё без ролей плагина; субпользователь сервера — просмотр, а с ролями `rust-autowipe.manage` / `.run` — изменения и запуск |

## Быстрый старт

1. Скопировать плагин в панель:

   ```bash
   docker cp ./rust-autowipe catalyst-backend:/var/lib/catalyst/plugins/rust-autowipe
   docker compose -f /opt/catalyst/catalyst-docker/docker-compose.yml restart backend
   ```

   Либо установить через маркетплейс панели — см. раздел ниже.

2. **Admin → Extensions → Plugins → Rust AutoWipe → Enable** (принять дисклеймер).

3. **Settings**: вставить `apiKey` — API-ключ панели с правами `server.read`,
   `server.start`, `server.stop`, `server.startup` (для сида/размера карты)
   и `console.write`, если нужны команды после запуска. `server.read` обязателен:
   по нему плагин узнаёт шаблон сервера и проверяет субпользователей. Для чата и
   для проверки субпользователей ключу нужен ещё `admin.write`: без него панель не
   отдаёт плагину список доступа чужого сервера, и субпользователи не видят вкладку
   (подробно — в руководстве, §5.1).

4. Открыть **сервер с шаблоном Rust** → вкладка **Rust AutoWipe** → создать профиль →
   расписание и пути → **«Что будет удалено»** → **«Проверка»** → **«Вайп сейчас»**
   (перед вайпом откроется окно с последствиями и кнопкой «Отмена»).

Подробно: [docs/RUST-AUTOWIPE-RU.md](docs/RUST-AUTOWIPE-RU.md).

## Привязка к серверу и яйцу

Вкладка объявлена так:

```js
{
  location: 'server',
  requiredPermissions: ['server.read'],
  templateFilter: { namePattern: 'rust' },
}
```

- Панель показывает её **только внутри сервера**, чей шаблон (яйцо) матчится
  регуляркой `namePattern` (без учёта регистра). `rust` покрывает «Rust»,
  «Rust Dedicated Server», «Rust (Oxide/uMod)» и т.п.
- Если ваш шаблон назван иначе — поменяйте `namePattern` в конце
  `rust-autowipe/frontend/frontend.mjs` и `RUST_TEMPLATE` в начале
  `rust-autowipe/backend/index.js` (backend проверяет имя шаблона по тому же правилу),
  пересоберите пакет и обновите плагин.
- Backend не верит фронтенду: каждый роут начинается с `/servers/:serverId/` и
  проверяет доступ к серверу. Пускает админа панели, владельца сервера и
  субпользователя — того, кто есть в списке доступа этого сервера в панели и у кого
  там есть `server.read`. Список доступа плагин читает своим API-ключом, cookie
  пользователя никуда не пересылает. Без API-ключа субпользователи получают отказ,
  а админ и владелец работают.
- Только Rust: backend сам отказывает серверу, у которого имя шаблона не содержит
  `rust` (без учёта регистра), — ответ `403` «Сервер не Rust…». Плановый вайп такого
  профиля пропускается, причина сохраняется в профиле (`lastSkipReason`). Если шаблон
  узнать нельзя (нет API-ключа), эта проверка пропускается.
- Профили и история прогонов изолированы по `serverId`: чужой профиль нельзя ни
  прочитать, ни изменить, ни запустить через роут другого сервера.

## Сид и размер карты

В профиле есть блок «Карта»:

- **Сид** (`WORLD_SEED`): не менять · случайный при каждом вайпе · фиксированный ·
  по списку по очереди (курсор хранится в профиле и двигается только после реальной записи).
- **Размер** (`WORLD_SIZE`): не менять · фиксированный (1000–6000) · случайный из набора.
- Имена переменных можно изменить, но в имени сида должно быть `SEED`, в имени
  размера — `SIZE`, и это две разные переменные: другие переменные шаблона плагин
  не меняет. Кнопка **«Определить из шаблона»** читает
  `GET /api/servers/:id/variables` и подставляет найденные `*SEED*` / `*SIZE*`
  (значения вкладка получает только у них, у остальных — одни имена).

Порядок: `stop → поиск путей → PATCH /variables → удаление файлов → start`. Если поиск
путей упал или упёрся в предел, переменные не меняются. Если удалять нечего, сид и размер
всё равно меняются (так решил владелец), а прогон считается ошибкой. В dry-run значения
только показываются, переменные не меняются. Ошибка записи прерывает вайп до удаления и
поднимает сервер обратно.

> Нужно, чтобы startup шаблона использовал `{{WORLD_SEED}}` и `{{WORLD_SIZE}}`
> (стандартное Rust-яйцо так и делает). API-ключу требуется право `server.startup`.

## Подключение к маркетплейсу Catalyst

Репозиторий сам служит индексом маркетплейса: `index.json` в корне ссылается на
пакет в `dist/` ветки `main`. Панель сверяет sha256 пакета с индексом — это защита от
файла, испорченного при скачивании, но не от подмены: пакет и сумма лежат в одном
репозитории. Что попало в `main`, панели видят сразу (см. «Как выпустить новую версию»).

1. **Admin → Extensions → Marketplace → Marketplaces → Add**:
   - **URL**: `https://raw.githubusercontent.com/kafder100/RustWipe/main/index.json`
   - **Label**: `RustWipe`
2. Вкладка **Marketplace** → найти **Rust AutoWipe** → **Install**
   (панель скачает zip, сверит sha256 и положит код на диск выключенным).
3. **Admin → Extensions → Plugins → Rust AutoWipe → Enable** → принять дисклеймер.
4. **Settings** → `apiKey` (см. выше).

Панель кэширует индекс 5 минут: после публикации новой версии нажмите в маркетплейсе
«обновить»; кнопка **Update** появится, когда версия в `index.json` станет выше
установленной.

> `raw.githubusercontent.com` кэширует файлы ещё примерно на 5 минут и не пробивается
> заголовком `no-cache`. Сразу после `git push` панель может видеть старую версию —
> подождите несколько минут. Сам пакет лежит по новому URL (`…-1.2.0.catpkg.zip`),
> поэтому он не кэшируется и после обновления индекса ставится сразу.

### Как выпустить новую версию

```bash
# 1. поднять version в rust-autowipe/plugin.json и в объекте manifest в конце
#    rust-autowipe/frontend/frontend.mjs; добавить раздел «## x.y.z» в начало CHANGELOG.md
# 2. пересобрать пакет и индекс (base-url уже указывает на этот репозиторий)
python tools/pack.py
# 3. проверить локально
node tools/test.mjs && node tools/ui-smoke.mjs && node tools/review/run.mjs
# 4. отправить в отдельную ветку и открыть pull request в main
git switch -c release-x.y.z
git add -A && git commit -m "release: rust-autowipe x.y.z"
git push -u origin release-x.y.z
# 5. CI зелёный — слить pull request в main: с этого момента панели видят версию
# 6. метка на коммите из main: release.yml ещё раз прогонит проверки,
#    пересоберёт пакет, сверит его с закоммиченным и создаст GitHub Release
git switch main && git pull
git tag vx.y.z && git push origin vx.y.z
```

`pack.py` в конце запускает `check_index.py`. Он падает, если разошлись sha256, версия
(`plugin.json`, `index.json`, `CHANGELOG.md`, frontend, zip), состав архива или код в
архиве и в `rust-autowipe/`. Сборка воспроизводимая: одинаковые исходники дают тот же
пакет, а уже собранный пакет той же версии сравнивается по содержимому.

> **CI не отзывает выпуск задним числом.** Панели берут пакет из `index.json` ветки
> `main`, как только коммит туда попал, а CI запускается уже после push. Версию с ошибкой
> останавливает только порядок работы: проверки локально и pull request с зелёным CI до
> слияния в `main`. Надёжнее всего защитить ветку `main` в настройках репозитория GitHub:
> слияние только через pull request, обязательные проверки CI, без force-push. И включить
> двухфакторный вход: кто может писать в `main`, тот может выложить панелям любой пакет —
> подписи пакетов Catalyst не проверяет. `push_to_github.mjs` обновляет ветку напрямую —
> для выпуска указывайте `--branch release-x.y.z` и открывайте pull request.

Релиз можно создать и вручную, без тега:

```bash
GH_TOKEN=... node tools/release_github.mjs          # текущая версия из plugin.json
```

Скрипт идемпотентен: описание и топики репозитория обновляются, существующий релиз
не пересоздаётся, уже загруженный ассет не заменяется — он сверяется по sha256, и другой
файл с тем же именем даёт ошибку. Релиз создаётся только из коммита на GitHub, где
`index.json` ведёт ровно на этот пакет: сначала отправьте коммит выпуска в `main`.

Если хочется вместо raw-ссылки использовать GitHub Releases, соберите пакет с
`--base-url https://github.com/kafder100/RustWipe/releases/download/v<версия>` и
приложите zip к релизу — остальное (sha256, индекс) не меняется.

## Структура репозитория

```
rust-autowipe/            каталог плагина (имя = name в plugin.json)
  plugin.json             манифест: права, конфиг, события
  backend/                серверные роуты /servers/:serverId/…, планировщик, fileTunnel
    lib/warnings.js       предупреждения в чат перед плановым вайпом (окно, дедуп)
  frontend/frontend.mjs   self-contained UI серверной вкладки (без React-хуков и импортов)
docs/RUST-AUTOWIPE-RU.md  полное руководство (установка, настройка, диагностика)
CHANGELOG.md              история версий
index.json                индекс маркетплейса (его URL добавляют в панель)
tools/test.mjs            тесты backend-логики и доступа к серверу
tools/ui-smoke.mjs        дымовой тест UI на DOM-шиме
tools/review/             тесты ревью: песочница без панели, run.mjs и *.test.mjs
tools/preview-paths.mjs   автономная страница со строкой пути + замер зазоров браузером
tools/preview-app.mjs     локальный стенд: настоящий frontend.mjs + мок-API панели
tools/pack.py             сборка .catpkg.zip + sha256 + index.json
tools/check_index.py      проверка индекса, пакета и схемы plugin.json (он же в CI)
tools/catalyst_manifest.py  повтор zod-схемы манифеста Catalyst
tools/push_to_github.mjs  публикация через GitHub REST API: файлы — из git, без секретов
tools/release_github.mjs  метаданные репозитория и GitHub Release с пакетом
.github/workflows/        ci.yml — тесты и проверка пакета; release.yml — выпуск по метке
dist/                     собранный пакет .catpkg.zip и .sha256
```

## Разработка

```bash
node tools/test.mjs                 # логика: расписание, маски, прогон вайпа
node tools/ui-smoke.mjs             # рендер UI без браузера
python tools/pack.py                # пересобрать пакет + индекс + проверка
python tools/check_index.py         # только проверка индекса/пакета/манифеста
```

Проверка кода в панели:

```bash
curl -X POST https://panel.example.com/api/plugins/rust-autowipe/reload \
  -H "Authorization: Bearer $CATALYST_API_KEY"
```

## Совместимость

- Catalyst **>= 1.80.0** (манифест), тестировалось на **1.89.0**.
- Node.js 20+ (панель столько и требует). Backend Catalyst v1.89.2 работает на Node 22;
  CI проверяет плагин на Node 22 и 24 в поясах UTC, Europe/Moscow и America/New_York.
- Rust Dedicated Server: `server/<identity>/`, имена файлов с protocol-суффиксом
  (`proceduralmap.*.map|sav`, `player.blueprints.*.db`, `sv.db`), поэтому в пресетах маски.

## Ограничения

- Удаление необратимо: первый прогон — только dry-run и с бэкапом.
- Ссылку в середине пути (например, если сама папка `/oxide/data` — ссылка на другую
  папку) и точку монтирования (папку, к которой подключён другой диск) плагин не видит:
  то, что за ними, удалится как обычные файлы. Ссылки и подключённые папки не должны
  попадать в то, что удаляет профиль.
- Чего в плагине сознательно нет — см. [«Чего в плагине нет»](docs/RUST-AUTOWIPE-RU.md#чего-в-плагине-нет).
- Плагин работает в процессе backend панели — как и любой плагин Catalyst.
