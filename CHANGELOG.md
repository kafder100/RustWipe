# Changelog

## 1.3.6 — 2026-11-16

- Убран лишний зазор между ручкой перетаскивания и номером строки: колонки поджаты
  до `0.85rem` и `1.3rem`, номер выровнен по левому краю, отступ сетки — `6px`.

## 1.3.5 — 2026-11-16

- **Вёрстка строки пути починена:** вместо flex — жёсткая сетка «ручка · номер · путь ·
  кнопки», путь выровнен по левому краю и обрезается многоточием, счётчик выровнен
  по правому краю, кнопки прижаты вправо.
- **Иконки действий белые** (цвет `--rw-fg`), при наведении подсвечиваются; красный
  остался только у `×` при наведении.
- **Перетаскивание мышью:** за ручку `⠿` строку можно тащить вверх и вниз, линия
  вставки показывает, куда она встанет. Кнопки `↑` / `↓` сохранены для точной
  правки и клавиатуры.

## 1.3.4 — 2026-11-16

- **Списки «Что удалять (пути и маски)» и «Исключения» стали управляемыми:** у каждой
  строки появились кнопки `↑` / `↓` (перемещение), `✎` (правка по месту), `⧉`
  (дублировать) и `×` (удалить).
- Правка по месту: поле получает фокус, курсор в конце строки; `Enter` сохраняет,
  `Esc` отменяет, уход фокуса тоже сохраняет. Одинаковые пути после правки
  схлопываются с сохранением порядка.
- Дубликат вставляется сразу под исходной строкой — удобно скопировать путь и
  поправить маску в копии.

## 1.3.3 — 2026-11-16

- **Выбор файлов больше не теряет профиль.** Клик по затемнению в редакторе профиля
  больше ничего не закрывает; в выборе файлов такой клик возвращает в редактор с
  сохранённым черновиком вместо потери всех настроек.
- В шапке выбора файлов появилась кнопка «← Назад к профилю», а в списке — строка
  «На уровень выше»: переход к родительскому каталогу берётся из хлебных крошек,
  выйти за корень сервера нельзя.
- Закрытие предпросмотра «что будет удалено» больше не сбрасывает редактор профиля.
- Версия во фронтенд-манифесте синхронизирована с `plugin.json` (была 1.2.0).

## 1.3.2 — 2026-11-16

- **Переделан вид шагов в истории:** сводная строка — номер, локальное время с
  миллисекундами, действие и длительность справа; в раскрытии — полный текст шага и
  метрики отдельной таблицей «ключ → значение» с выравниванием по колонкам.
- Убран дублирующий блок «время / длительность / результат» внутри раскрытия и повтор
  текста шага в свёрнутой строке.
- Из текстов шагов убраны кавычки-ёлочки: шрифт панели не отрисовывал «», вместо них
  появлялись квадраты. Формулировки вида `статус «running»` заменены на `статус running`.

## 1.3.1 — 2026-11-16

- **Исправлено:** запись переменных карты (`WORLD_SEED`/`WORLD_SIZE`) падала, даже когда
  у ключа есть `server.startup`: панель принимает только полный набор переменных и отвечает
  `422 This field is required` на остальные. Теперь плагин дочитывает текущие значения
  через `GET /api/servers/:id/variables` и отправляет их вместе с изменениями.
- Ключу плагина нужны `server.read` (чтение переменных) и `server.startup` (запись).

## 1.3.0 — 2026-11-16

- **Подробная статистика по шагам вайпа.** В истории запусков каждый шаг раскрывается
  и показывает точное время, длительность фазы, полный текст деталей и числовые метрики.
- Бэкенд пишет в шаг `data`: `ms` (длительность), плюс `paths` / `truncated` для поиска
  путей, `deleted` / `skipped` / `errors` для удаления, `seed` / `size` для карты,
  `status` для остановки и запуска, `message` для ошибки.
- Для шага «удаление» в раскрытии доступны списки удалённых и пропущенных путей,
  для прогона — списки ошибок и предупреждений.
- Прогоны, записанные до 1.3.0, открываются как раньше: без `data` шаг показывает
  время и текст, метрики просто не выводятся.

## 1.2.0 — 2026-11-16

- **Сид и размер карты**: блок «Карта» в профиле. `WORLD_SEED` — случайный каждый вайп /
  фиксированный / по списку по очереди; `WORLD_SIZE` — фиксированный (1000–6000) или
  случайный из набора.
- Значения записываются в переменные шаблона через `PATCH /api/servers/:id/variables`
  после остановки и до удаления файлов; ошибка записи прерывает вайп и поднимает сервер.
- Курсор ротации хранится в профиле и двигается только после реальной записи; фактические
  сид/размер пишутся в историю прогона.
- Кнопка «Определить из шаблона» подтягивает имена переменных из панели.
- API-ключу плагина теперь нужно право `server.startup` (для записи переменных).
- У профилей без поля `map` (созданных до 1.2.0) сохраняется прежнее поведение —
  карта не меняется.

## 1.1.1 — 2026-11-15

- Убрано неиспользуемое право `rust-autowipe.view`: доступ к вкладке определяется
  встроенным `server.read` на сервере, а изменения и запуск — `rust-autowipe.manage`
  и `rust-autowipe.run`.
- Уточнены README и руководство по привязке к серверу/яйцу.

## 1.1.0 — 2026-11-15

- Плагин стал **серверной вкладкой**: `location: 'server'` + `templateFilter: { namePattern: 'rust' }`.
  Вкладка видна только в карточке сервера с шаблоном (яйцом) Rust, панельная вкладка удалена.
- Все API-роуты переехали под `/servers/:serverId/…`; профили и история изолированы по серверу.
- Проверка доступа к серверу на каждом роуте: владелец, админ панели либо подтверждение
  панели по cookie/ключу вызывающего (для субпользователей).
- Роли `rust-autowipe.manage` / `.run` управляют изменениями и запуском; владелец сервера
  получает доступ только на чтение.

## 1.0.1 — 2026-11-15

- Индекс маркетплейса переехал в корень репозитория (`index.json`), `downloadUrl`
  указывает на пакет в `dist/`; панель ставит плагин прямо с GitHub.
- CI проверяет схему `plugin.json`, `index.json`, sha256 пакета и allowlist записей
  zip (`tools/check_index.py`) на каждый push.
- `tools/pack.py` запрещает пересобирать уже выпущенную версию с другим содержимым —
  иначе sha256 в индексе разъезжается с закэшированным CDN файлом.
- GitHub Release `v1.0.1` с приложенным пакетом; авто-релиз по тегу
  (`.github/workflows/release.yml`).

## 1.0.0 — 2026-11-15

Первый релиз.

- Расписание вайпов: еженедельно, «первый/последний N-й день недели месяца»
  (под Force Wipe Facepunch), день месяца, каждые N дней. Время — в часовом поясе панели.
- Выбор файлов и каталогов: файловый пикер по дереву сервера, маски `*` / `?` / `**`,
  отдельный список исключений.
- Rust-пресеты: карта, карта + блюпринты, данные игроков, полный вайп
  (с сохранением `cfg/server.cfg`), данные Oxide/Carbon.
- Порядок вайпа: остановка → удаление → запуск через REST API панели; при ошибке после
  остановки сервер поднимается обратно.
- Dry-run, предпросмотр «что будет удалено», история прогонов с шагами.
- Права для ролей панели: `rust-autowipe.view`, `rust-autowipe.manage`, `rust-autowipe.run`.
